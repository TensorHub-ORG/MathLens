# MathLens 产品愿景

状态：Active
最后更新：2026-08-21

## 一句话定义

MathLens 是一个开放、可验证、可扩展的数学文档智能与推理平台，将原始数学文档转换为
可追溯的结构化知识，并通过可组合的 Skill 完成重构、学习、研究和形式化验证工作流。

## 问题

大量数学资料以扫描 PDF、低质量图片或陈旧排版文件存在。它们缺少可靠文本层、公式结构
和题目语义，不能直接被搜索、重排或交给推理模型。通用 OCR 即使整体观感良好，也可能
把负号、上下标、转置、量词或矩阵边界识别错误；一个局部错误就足以改变整道题。

现有工具通常只解决其中一个环节：解析、OCR、LaTeX、解题或证明验证。MathLens 要解决
的是这些环节之间缺少统一数据模型、质量评价、来源追踪和可复现工作流的问题。

## 使命

让数学文档中的每一个结构和结论都能回答三个问题：

1. 它来自原文哪里？
2. 它经过了哪些工具、模型或人工修改？
3. 它以什么强度得到验证？

## 目标用户

- 需要整理扫描试卷和教材的学生、教师与题库维护者；
- 需要重构旧论文、讲义和书籍的研究人员；
- 需要批量构建数学语料、评测集和知识库的开发者；
- 希望贡献数学领域解析、推理或验证能力的开源社区成员。

## 产品支柱

### 可追溯

任何文本、公式、图像、结构和答案都保留原始页码、坐标、裁剪图、候选结果、执行版本
和修改记录。生成内容不得伪装成原文内容。

### 可验证

质量依靠 golden dataset、编译检查、视觉比较、符号计算、反例搜索和形式化证明等分层
证据衡量，不以“模型看起来正确”作为验收标准。

### 可组合

文档解析、翻译、解题、验证和输出通过类型化 artifact 连接。工作流可以替换节点，而不
需要重写整个系统。

### 可扩展

Lean、SymPy、MinerU、翻译模型和未来工具通过 Adapter、Verifier 或 Skill 接入，避免把
具体引擎写死在核心中。

### 本地优先

用户文档默认在本地处理。联网、外部模型和远程服务必须显式配置，并在执行记录中可见。

## 产品分层

### MathLens Core

负责 PDF、图片、页面、MathIR、artifact、来源追踪、文档结构、LaTeX 基础能力和评价体系。
Core 不负责自由式 Agent 编排，不依赖具体大模型，也不内置领域 Skill。

### MathLens Flow

未来的工作流运行时，负责任务图、缓存、恢复、模型路由、权限、资源限制、人工审核节点和
Skill 生命周期。`Flow` 是 MathLens 的子系统名称，不是另一个产品名称。

### MathLens Skills

面向用户目标的可安装能力包，例如学术翻译、证明验证、题目解析、知识点标注和多解法
生成。Skill 可以组合 Agent、Adapter 和确定性 Verifier，但不等同于其中任何一个。

### MathLens Studio

未来的 Tauri 桌面工作台，提供原页、结构树、公式候选、人工校对、编译预览、验证证据和
工作流编辑界面。

### MathLens Hub

达到安全、兼容和治理要求后建设的 Skill 注册与发现服务。它不是当前阶段目标。

## 内容真实性边界

MathLens 必须严格区分：

- `source_transcription`：对原文的忠实转录；
- `normalized_content`：排版或语义规范化结果；
- `generated_content`：模型生成的解释、答案或翻译；
- `verification_evidence`：支持或反驳某个结论的证据。

任何规范化和生成操作都不得覆盖原始转录。

## 验证承诺

MathLens 不承诺所有数学答案都能得到形式化证明。Lean 验证只能证明形式化命题在指定定义、
公理和假设下通过内核检查，不能自动保证 OCR 与形式化命题忠实对应原题。

平台应报告验证等级，而不是单一布尔值：

- 已通过形式化验证；
- 在列出假设下验证；
- 仅通过内核检查，题意等价性未确认；
- 通过符号或数值检查；
- 找到反例；
- 无法验证或暂不支持。

## 当前非目标

- 立即建设通用 Agent 框架或 Skill Marketplace；
- 把所有数学工具塞入基础安装；
- 默认逐像素复刻所有原始版式；
- 声称 Lean 可以验证所有自然语言答案；
- 用多个 Agent 自由对话代替结构化工作流；
- 在缺少评测数据时根据主观观感选择 OCR 模型；
- 为尚不存在的第三方插件保留历史兼容逻辑。

## 成功标准

近期成功不是 Skill 数量，而是第一条真实闭环：

1. 从真实扫描 PDF 中选取有代表性的页面；
2. 生成带来源坐标的 MathIR；
3. 产出可维护、可编译的 LaTeX；
4. 对文字、公式、版面和结构给出可复现评测；
5. 只让人工复核不确定区域；
6. 任意结果可以追溯到输入、工具版本和配置。

长期成功由以下指标衡量：

- golden dataset 上的文本、公式、版面和结构准确率；
- 低置信区域召回率与人工修改成本；
- LaTeX 编译率和视觉/语义一致性；
- 工作流复现率与失败恢复能力；
- Skill 的兼容性、安全性、测试质量和维护状态；
- 用户能够独立完成的真实数学文档工作流数量。

## 决策过滤器

新增功能或依赖前必须回答：

1. 它解决了目标用户的哪个真实问题？
2. 它属于 Core、Flow、Skill、Adapter 还是 Verifier？
3. 输入输出是否是明确版本的结构化类型？
4. 是否保留来源、版本、配置和验证证据？
5. 如何在 golden dataset 或集成测试中衡量它？
6. 能否在不破坏核心的情况下替换或删除？
7. 当前里程碑是否真的需要它？

不能清楚回答的问题，不进入当前实现。
