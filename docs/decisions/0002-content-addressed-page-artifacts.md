# 0002：内容寻址的页面图 Artifact

状态：Accepted
日期：2026-08-21

## 背景

扫描 PDF 必须先稳定渲染为页面图，才能交给 MinerU、公式识别或人工标注。若工作流只传递
临时图片路径，结果会失去输入哈希、渲染配置、工具版本和坐标关系，无法复现或安全缓存。
同时，绝对源路径可能包含用户隐私，不应成为可共享 manifest 的必要字段。

## 决策

1. 页面渲染结果使用版本化 Schema `mathlens.page-image.v1`。
2. 每个页面是独立、不可变的 artifact，目录由 `artifact_id` 分层寻址，包含 `page.png` 和
   `manifest.json`。
3. `content_hash` 只标识 PNG 字节；`artifact_id` 同时绑定源文档哈希、页码、内容哈希、配置、
   引擎版本和页面元数据，避免把来源不同的结果误认为同一次推导。
4. manifest 记录源文件名和 SHA-256，但不记录绝对路径。运行报告可以保留本地路径。
5. 坐标映射以 PyMuPDF 展示后的页面矩形为 PDF 点坐标空间，记录实际像素宽高计算出的横纵
   比例。使用实际比例而不是假定 `dpi / 72`，以保留整数像素取整后的可逆关系。
6. 已发布目录不得覆盖。重复发布相同 artifact 时验证 manifest 与内容哈希后复用；发现缺失、
   冲突或损坏立即失败。

## 后果

- OCR block 可以通过明确变换映射回原页坐标；
- 相同输入、配置和引擎版本得到相同 artifact ID，可用于缓存和回归评测；
- 更新 PyMuPDF 或渲染配置会产生新 artifact，不会静默覆盖旧结果；
- 页面 PNG 会占用额外磁盘，后续需要独立的保留与清理策略；
- 当前文件系统存储可以被其他实现替换，而不改变渲染器或消费方。

## 未选择的方案

### 直接按页码覆盖图片

无法区分输入、配置和引擎版本，旧结果也无法审计。

### 只使用 PNG 内容哈希作为 Artifact ID

视觉字节相同不代表来源和推导过程相同，会丢失 MathLens 所要求的 provenance 身份。

### 在 Manifest 中保存绝对源路径

绝对路径不可移植，也可能泄露用户名、组织目录或资料存放方式。
